# 种子改写增强 提示词模板

## 角色定义
你是一个数据合成专家，精通**种子数据改写增强**（Seed Rewriting Augmentation）。

## 任务背景
种子改写增强从**已有的种子数据对**（instruction + response）出发，在**保持任务本质不变**
的前提下做表达层与结构层的变换，把少量种子扩写成多个平级可用的变体。

它是"扩量"范式：**不提升难度**，只增加同一任务的不同问法/格式/场景，
因此产出的数据可以直接和种子数据混在一起用于指令微调（SFT）。

### 与 Evol-Instruct 的区别（重要）
本范式**不是** Evol-Instruct 的「指令改写」分支，两者目标相反：

| | Evol-Instruct（含其改写分支） | 种子改写增强（本模板） |
|---|---|---|
| 目标 | **加难 / 加宽**：让指令更复杂、跨度更大 | **保义扩量**：任务本质不变，只换表达 |
| 变体难度 | 逐级上升（简单→中等→复杂） | **与原种子持平** |
| 回答能否复用 | 往往需重写 | **原回答常常仍然正确** |
| 用途 | 提升模型能力上限 | 增加同任务的样本覆盖 |

**自检标准：** 改写后的指令与原种子是否"问的是同一件事"——是则通过；
若已经变成更难或另一个任务，则属于 Evol-Instruct 的职责，本范式不产出。

## 核心流程

### 第一步：理解种子
读取每条种子的 instruction 与 response，判断：
- 核心任务是什么（翻译 / 代码 / 写作 / 摘要 / 分类 / 问答 …）
- 回答里承载了哪些**必须保留的信息**（如代码的算法、邮件的要素、摘要的结论）

### 第二步：选择改写策略并生成变体
对每条种子，从下列策略中选 **4-6 种不同策略**，各生成 1 个变体：

| 策略 | 说明 | 示例（种子：总结这篇文章） |
|---|---|---|
| 同义改写 | 换词换句式，语义不变 | "概述这篇文章的主要内容" |
| 句式变换 | 陈述↔疑问↔祈使 | "请用一句话告诉我，这篇文章讲了什么？" |
| 格式约束 | 指定 JSON / 表格 / 列表输出 | "用 JSON 输出摘要，含 title 和 summary 字段" |
| 长度与风格 | 加字数或语气限制 | "用不超过 100 字、通俗易懂地总结" |
| 输入变换 | 改变输入的类型或载体 | "以下是会议纪要，请总结其主要观点：…" |
| 领域迁移 | 同任务换到另一领域 | "总结这份医疗报告的主要结论" |
| 角色设定 | 加一个合理的身份前缀 | "你是一名编辑，请总结这篇文章的核心观点" |

**变体数量（硬性要求，必须自检）：** 每条种子生成 **4-6 个变体**，且**每个变体的
`rewrite_type` 必须互不相同**。写完后自己数一遍：`variants` 数组的长度，
必须等于该种子用到的**不同策略数**。

> ⚠ 反面示例（真实实测中出现过，严禁照做）：
> 一条种子只给 2 个变体、且两个都标注 `同义改写`。
> 这**同时违反**两条要求：数量没到下限 4，策略也没去重。
> 出现这种情况说明该种子的改写任务**没有完成**，必须补足到 4-6 个。

### 第三步：重写配套回答
变体的 instruction 变了，response 必须**同步改写**，并满足：

1. **若任务未变**（同义改写、句式变换、角色设定）→ 原回答的事实内容仍然成立，
   按其新措辞重写即可，**不得丢失原回答的关键信息**；
2. **若加了新约束**（格式 / 长度 / 风格）→ 必须严格满足该约束
   （要求 100 字就是 100 字以内，要求 JSON 就必须是合法 JSON）；
3. **若换了领域或输入**（领域迁移、输入变换）→ 回答必须与新领域/新输入自洽，
   不得残留原领域的内容；
4. 回答长度与种子回答**保持同一量级**，不要为了凑字数而注水。

### 第四步：一致性自检
逐条检查，任一项不满足就重做该变体：
- [ ] 变体的任务类型与原种子**相同**（不是另一个任务）
- [ ] 变体难度与原种子**持平**（没有变难也没有变简单到无意义）
- [ ] response 完整回答了 variant 的 instruction，且满足其**全部**约束
      （指令要求写什么就真的写了什么，不能漏项）
- [ ] instruction 与 response 均为中文（代码、专有名词、公式除外）
- [ ] 不含任何真实个人信息（见「注意事项 4」）

写完后还要做**整批自检**（针对每条种子）：
- [ ] `variants` 长度在 **4-6** 之间
- [ ] 各变体的 `rewrite_type` **互不重复**
- [ ] 每个 `response` 都满足**它自己那条**指令的全部约束（含字数/行数限制）
- [ ] **每一条**输入种子都产出了变体，没有遗漏

> 注意：**不要**检查"回答是否两两不同"。对纯换表达的变体，回答相同是正确的 ——
> 换表达的任务本来就应该得到同一个答案。要查的是上一条"是否满足各自指令"。

## 输出要求

**输出格式（JSON）：**

```json
{
  "seed_rewrites": [
    {
      "original_instruction": "用 Python 写一个函数，判断一个整数是否为素数",
      "variants": [
        {
          "rewrite_type": "同义改写",
          "instruction": "请编写一个 Python 函数，用来检测给定的整数是不是素数",
          "response": "def is_prime(n):\n    ..."
        },
        {
          "rewrite_type": "句式变换",
          "instruction": "怎么用 Python 判断一个整数是不是素数？请给出函数实现",
          "response": "def is_prime(n):\n    ..."
        },
        {
          "rewrite_type": "格式约束",
          "instruction": "用 Python 实现素数判断函数，并以 JSON 输出，含 code 和 explanation 两个字段",
          "response": "{\n  \"code\": \"def is_prime(n): ...\",\n  \"explanation\": \"...\"\n}"
        },
        {
          "rewrite_type": "角色设定",
          "instruction": "你是一名算法面试官，请写一个 Python 素数判断函数作为参考答案",
          "response": "def is_prime(n):\n    ..."
        },
        {
          "rewrite_type": "长度与风格",
          "instruction": "用不超过 5 行的 Python 代码判断一个整数是否为素数",
          "response": "def is_prime(n):\n    ..."
        }
      ]
    }
  ]
}
```

**字段说明：**
- `original_instruction`：该种子指令原文（**放在种子层级**，一条种子只写一次）
- `variants`：该种子的改写变体数组
  - `rewrite_type`：**放在每个变体内部**，标明该变体用的是哪种策略
    （**必须**从上表七种策略中取一个，且同一 `variants` 数组内**不得重复**）
  - `instruction`：改写后的指令
  - `response`：与该变体指令**严格匹配**的完整回答

> 上面示范的第一条种子给了 **5 个变体、5 种不同策略** —— 这只是**格式示范**。
> 请按「第二步」的硬性要求，为**每一条**输入种子都产出 4-6 个变体，
> **不要**因为示例里只展示了一条种子就只处理一条。

## 注意事项

1. **语义保持是底线**：改写后必须与原种子"问的是同一件事"，这是本范式区别于
   Evol-Instruct 的唯一标准。
2. **难度持平**：不要把"写一封邮件"改写成"设计一套邮件系统架构"，那是进化不是改写。
3. **回答必须真实可用**：代码要能跑、JSON 要合法、算出来的结果要对；
   不允许出现"此处省略""略"之类的占位。
4. **PII 安全（重点）**：示例中的邮箱一律用保留域名 `example.com`，
   电话一律用掩码形式（如 `010-8888XXXX`），姓名用"张三/李四/X 先生"等虚构形式。
   **禁止使用 `abc.com`、`xyz.com`、`qq.com` 等真实注册域名，禁止真实手机号。**
5. **格式规范**：最终只输出一个合法 JSON，不要代码块围栏、不要解释文字。
6. **多样性（硬性）**：同一条种子的多个变体必须使用**不同策略**，`rewrite_type` 互不重复。
   实测出现过"一条种子只给 2 个变体、且两个都标同义改写"，这属于**未完成任务**。
7. **回答必须匹配各自的指令（重点）**：每个变体的 `response` 要**单独**满足该变体指令的
   **全部**约束。实测出现过：指令要求"说明调休原因和交接安排"，回答却只写了交接安排、
   漏掉原因 —— 这属于不合格，必须重写。

   ⚠ **不要为了"避免重复"而故意改动正确的回答。** 对纯换表达的变体
   （同义改写 / 句式变换 / 角色设定），任务本质没变，**回答相同是正确的、也是预期的** ——
   这正是在教模型"同一任务的多种问法应得到同样的答案"。只有变体**新增了约束**
   （格式约束 / 长度与风格 / 输入变换 / 领域迁移）时，回答才必须相应改变。

8. **数量下限**：每条种子 4-6 个变体。宁可在输入种子多时少产出几条，
   也不要把某条种子压缩到 2 个变体。
9. **数量类约束必须精确满足（易错）**：写完带"不超过 N 字 / N 行"的回答后，
   **回头数字数**（中文字符、标点、换行都算），超出就压缩到限制内。
   实测 15 条里有 2 条超出（限 80 字写了 89、限 30 字写了 31）——
   这类约束是**可以机械核验**的，不要凭感觉。

## 开始执行

请对以下种子数据对执行改写增强。每条种子生成 **4-6 个变体**，策略不重复：

**种子 1：**
```
instruction: 用 Python 写一个函数，判断一个整数是否为素数
response: def is_prime(n):\n    if n < 2:\n        return False\n    for i in range(2, int(n ** 0.5) + 1):\n        if n % i == 0:\n            return False\n    return True
```

**种子 2：**
```
instruction: 撰写一封申请调休的请假邮件
response: 主题：调休申请\n\n王经理：\n\n您好！因个人事务需处理，我申请于 3 月 14 日（周五）调休一天，当日工作已与李四交接完毕，紧急事项可随时电话联系我。\n\n恳请批准，谢谢！\n\n张三\n2026 年 3 月 11 日
```

**种子 3：**
```
instruction: 总结下面这段话的主要观点：远程办公提高了员工的时间灵活性，但也模糊了工作与生活的边界，长期看需要企业建立更清晰的沟通规范。
response: 主要观点：远程办公有利有弊——它提升了时间灵活性，却模糊了工作与生活的边界；因此企业需要建立更清晰的沟通规范来应对。
```

**输出要求：**
- 每条种子 4-6 个变体，覆盖**不同**改写策略
- 变体难度与种子持平，任务本质不变
- 直接输出完整 JSON（`seed_rewrites` 结构），不要任何多余文字
